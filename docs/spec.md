# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

福岡で Web と AI の開発を学ぶ Gaku1205 の作品4つを、画像と文字・余白で見せるポートフォリオサイト。（元のメモ：Gaku1205 の作品を見せるポートフォリオサイト（作り直し・3回目））

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 使う人：Gaku1205 の作品を見に来た人（インターンや開発の仲間を探す人、勉強会で会った人、GitHub から来た人）
  - 場面：リンクを開いて最初の1画面で「AI に開発を回させる仕組みを作っている人」と分かり、気になった作品の画面を見て、公開ページか GitHub へ進む
  - PC でもスマホでも、数十秒で4つの作品を見比べられることが大事
- 技術：Next.js（App Router）＋TypeScript、テストはVitest

## 画面

### 最初の画面（`/`）

- 最初の画面・目次・作品の段（作品ごと）・できること・わたし・終わりの帯を縦に並べる
- 作品の段には、その作品の詳しいページへ入れるリンクを置く。画面を持つ作品は「画面をもっと見る」、画面を持たない仕組み（ai-dev-template）は「進み方を詳しく見る」。同じタブで開く

### 作品の詳しいページ（`/works/[id]`）

- `[id]` は `src/lib/works.ts` の `WORKS` の `id`。ビルド時に全作品ぶんを作る（`generateStaticParams`）。`WORKS` に無い id は 404（`notFound()`）
- 出す物（上から）：
  1. 「トップに戻る」リンク（`/` へ。ページの上と下の2か所）
  2. 作品の番号・種類、名前・日本語の名前・1行の説明
  3. 「何か」「どう作ったか」、「使った物」のタグ、リンク（公開ページ・GitHub は新しいタブで開く）
  4. 画面を持つ作品：スクロールした画面の画像。PC の画像を縦に1枚ずつ（4枚）、そのあとスマホの画像を並べて（4枚）見せる。1枚ごとに「PC 1 / 4」のような番号を付ける。画像は上から順（ページの上から下へスクロールした順）
  5. 画面を持たない仕組み：進み方の図（作業ログ）と「この工場が作った物」。作った物の画像を押すと、その作品の詳しいページへ移る
- 画像はすべて alt を持つ。PC の画像はその作品の名前と「何枚目か」を alt に入れる。スマホの画像も同様
- 画像は `src/lib/works.ts` の `WorkShots.scrolled`（`desktop` / `mobile` の配列、上から順）から読む。取り出しは `scrolledShots(work)`。画面を持たない作品は空の配列を返す
- どの幅でも横にスクロールが出ない（900px 以上・未満の両方）
