# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

福岡で Web と AI の開発を学ぶ Gaku1205 の作品6つを、画像と文字・余白で見せるポートフォリオサイト。（元のメモ：Gaku1205 の作品を見せるポートフォリオサイト（作り直し・3回目））

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 使う人：Gaku1205 の作品を見に来た人（インターンや開発の仲間を探す人、勉強会で会った人、GitHub から来た人）
  - 場面：リンクを開いて最初の1画面で「AI に開発を回させる仕組みを作っている人」と分かり、気になった作品の画面を見て、公開ページか GitHub へ進む
  - PC でもスマホでも、数十秒で6つの作品を見比べられることが大事
- 技術：Next.js（App Router）＋TypeScript、テストはVitest
- 公開：GitHub Pages（https://gaku1205.github.io）に、静的なサイトとして書き出して出す（`next.config.ts` の `output: "export"`）。サーバーで動く機能（API・画像の最適化・リクエストごとに変わる画面）は使わない。`[id]` のようなページは `generateStaticParams` で全部のページを書き出す

## 画面

### 最初の画面（`/`）

- 最初の画面・目次・作品の段（作品ごと）・できること・わたし・終わりの帯を縦に並べる
- 作品は6つ。いちばん上（01）は受賞作の「めぐりモノ」（`megurimono`）。ai-dev-template・agent-desk・atelier-journal・neon-sneaker-drop・neon-drift-arena は02〜06（06 が工場で作った Windows のゲーム）。目次・作品の段・最初の画面のカード・工場の「作った物」の番号は、`WORKS` の並び順から付く
- 受賞作（`award` がある作品）は、作品の段の名前の上に受賞の文字（めぐりモノは「AWS デジタル社会実現ツアー2025 九州 最優秀賞」）を出す。賞のロゴは使わない。目次と最初の画面のカードの種類の欄は「受賞作」
- 最初の画面のカードは、画面の画像を持つ最初の作品（めぐりモノ）を紹介する
- 追加の画像（`extras`。めぐりモノの出品一覧）は PC のみ。作品の図の下に1枚置く
- スマホの画面が無い作品（ゲームの neon-drift-arena。`shots.mobile` を省く）は、スマホの輪郭を出さず、PC の画面だけで見せる。最初の画面・作品の段の図は play の画像1枚で、追加の画像（`extras`。title・boss・over の3枚）は詳しいページに出す。リンクは「ダウンロード（Windows）」と GitHub
- めぐりモノのリンクは GitHub だけ（デモは止めているので、公開ページのリンクは出さない）。スクロールした画面は撮っていないので、詳しいページでは画面の列を出さない
- 作品の段には、その作品の詳しいページへ入れるリンクを置く。画面を持つ作品は「画面をもっと見る」、画面を持たない仕組み（ai-dev-template）は「進み方を詳しく見る」。同じタブで開く

### 作品の詳しいページ（`/works/[id]`）

- `[id]` は `src/lib/works.ts` の `WORKS` の `id`。ビルド時に全作品ぶんを作る（`generateStaticParams`）。`WORKS` に無い id は 404（`notFound()`）
- 出す物（上から）：
  1. 「トップに戻る」リンク（`/` へ。ページの上と下の2か所）
  2. 作品の番号・種類、名前・日本語の名前・1行の説明
  3. 「何か」「どう作ったか」、「使った物」のタグ、リンク（公開ページ・GitHub は新しいタブで開く）
  4. 画面を持つ作品：スクロールした画面の画像。PC の画像を縦に1枚ずつ、そのあとスマホの画像を並べて見せる。枚数は原則どちらも4枚。撮れない作品は撮れた分だけ出す（agent-desk は PC 2枚・スマホ 3枚）。1枚ごとに「PC 1 / 4」のような番号（分母はその作品の枚数）を付ける。画像は上から順（ページの上から下へスクロールした順）
  5. 画面を持たない仕組み：進み方の図（作業ログ）と「この工場が作った物」（atelier-journal・neon-sneaker-drop・neon-drift-arena）。作った物の画像を押すと、その作品の詳しいページへ移る
  6. スマホの画面が無く、スクロールした画面も無い作品（neon-drift-arena）：スクロールした画面の列は出さず、その位置に追加の画像（`extras`）を PC の枠に入れて縦に並べる。「スクロールした画面」「スマホ」の見出しは出さない（空の見出しを作らない）
- 作品の画像は 2 倍の細かさの webp。PC の画像（1440）はブラウザの枠（上に丸3つ＋アドレス。アドレスはその作品の URL）、スマホの画像（390）はスマホの輪郭に入れて見せる。作品の図は PC の窓の手前にスマホが少しかぶさる。枠は CSS で作る（`src/components/DeviceFrame.tsx`）。アドレスは `frameAddress(work)`（公開ページ、無ければ GitHub のリンク。どちらも無ければ最初のリンク）
- 画像はすべて alt を持つ。PC の画像はその作品の名前と「何枚目か」を alt に入れる。スマホの画像も同様
- 画像は `src/lib/works.ts` の `WorkShots.scrolled`（`desktop` / `mobile` の配列、上から順）から読む。取り出しは `scrolledShots(work)`。画面を持たない作品と、スマホの画面（`shots.mobile`）が無い作品は空の配列を返す
- どの幅でも横にスクロールが出ない（900px 以上・未満の両方）
